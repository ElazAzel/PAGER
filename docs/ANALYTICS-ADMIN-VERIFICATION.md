## Пользовательские изменения

- Автор открывает аналитику напрямую из нижней навигации или бокового меню: периоды 7/30/90 дней, график, источники, устройства, нажатия, обращения, подтверждённые результаты и поступления по валютам.
- В настройках страницы есть пример поискового сниппета и подсказки по содержанию. В редакторе доступны вопросы/ответы, фото и город автора, подписи кнопок. Проверяется черновик; это не измерение поисковых позиций.
- Администратор получает отдельный защищённый обзор платформы `/admin`: аккаунты, опубликованные страницы, агрегированные результаты, очереди и настройки сервисов. Операционные данные доступны для чтения; управление пользователями и возвратами из этой панели не добавлялось.
- Публичная публикация и доступные карточки товаров читаются в исходном HTML. Добавлены метаданные, канонические адреса, карточки ссылок, сведения об авторе, robots и sitemap. Закрытые тела, черновики и клиентские данные в поисковые материалы не передаются.
- На странице автора основная запись или заявка доступна в первом экране и закреплённой панели. Сохранены RU/EN и все 25 типов блоков. Приоритет телефона отражён в навигации, крупных кнопках и адаптивных сетках; компьютер использует широкую компоновку.

## Локальная проверка через HTTP и браузер

Production-сервер запущен локально на `http://127.0.0.1:3100` с изолированной папкой `.data/final-browser-check-20260903` и без provider keys. После запуска пройдены оба HTTP smoke-сценария: discovery/admin/analytics (43 проверки) и полный API (69 успешных assertions плюс проверки конфиденциальности, публикации, независимых доступов, подписок, остатков и записей). Параллельный запуск API один раз получил ожидаемый `409 Draft changed`; последовательный повтор прошёл полностью.

В браузере через UI использованы две локальные demo-сессии: автор `creator-anna` (также входит в demo allowlist администратора) и покупатель `buyer-primary` (отображается как Елена Смирнова). Реальные email, платежи, записи и внешние сервисы не использовались; booking в demo создаётся только в локальном хранилище.

Скриншоты финального чистого прогона сохранены в `output/private/browser-check-final-20260903/`:

- `home-mobile.jpg` — первый экран лендинга;
- `dashboard-mobile.jpg` и `dashboard-desktop.jpg` — кабинет автора и редактор;
- `public-mobile.jpg` и `public-desktop.jpg` — публичная страница автора;
- `booking-success-mobile.jpg` — подтверждение локальной записи;
- `analytics-mobile.jpg` и `analytics-desktop.jpg` — аналитика и воронковые действия;
- `admin-mobile.jpg` и `admin-desktop.jpg` — админ-обзор.

Запуск отдельного локального демо в PowerShell из папки PAGER:

```powershell
$env:PAGER_DEMO='true'
$env:PAGER_APP_URL='http://127.0.0.1:3100'
$env:PAGER_DATA_DIR='.data/discovery-verification-20260903'
$env:PAGER_DEMO_ADMIN_USER_IDS='creator-anna'
pnpm start --port 3100
```

В другом терминале (последовательно, на чистой папке данных для полного API-прогона):

```powershell
$env:PAGER_SMOKE_URL='http://127.0.0.1:3100'
pnpm test:discovery
pnpm test:api
```

Оба скрипта разрешают только loopback и проверяют, что сервер работает в деморежиме. `test:api` запускайте после `test:discovery`, а для повторов используйте отдельную свежую папку данных. Тестовые платежи и бронирования остаются симуляцией. Для интерфейса: открыть `/dashboard`, войти как демо-автор, проверить аналитику и настройки; ссылка администрирования появляется только у разрешённого аккаунта. Публичная страница — `/anna`. Визуально проверены 390×844, включая FAQ, основную кнопку, смену периода, поиск автора, RU/EN-переключатель и подтверждение записи. Для ПК отдельно открыты wide desktop tabs и сохранена широкая CSS-компоновка; production build также проверен.

## Настройка реального окружения

В рабочем окружении `PAGER_DEMO=false`. Администраторы задаются точными проверенными Supabase user ID в серверной переменной `PAGER_ADMIN_USER_IDS`; по умолчанию список пуст. Локальный demo allowlist игнорируется в этом режиме.

Для индексации нужен реальный HTTPS `PAGER_APP_URL`, опубликованная открытая страница и доступный поисковым ботам домен. Подтверждение домена, Search Console/Bing Webmaster Tools, обход, Core Web Vitals и фактические появления в ответах ИИ проверяются отдельно после размещения. Индексация и рост конверсии пока не измерены. Реальные Supabase/Stripe/Cal.com/Resend/Inngest не подтверждаются локальными тестами.
