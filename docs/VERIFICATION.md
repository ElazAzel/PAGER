# Проверка PAGER — 3 сентября 2026

Это промежуточная версия PAGER. Выбранное мобильное направление Page Studio реализовано в локальном MVP; реальные провайдеры и внешний HTTPS-стенд ещё не настроены.

## Подтверждено на общей версии кода

| Проверка | Результат |
| --- | --- |
| `pnpm typecheck` | Успешно |
| `pnpm lint` | Успешно, без предупреждений |
| `pnpm test` | 109 тестов, 17 файлов — успешно |
| `pnpm build` | Успешно; API-маршруты, без предупреждения о трассировке всей рабочей папки |
| `pnpm exec supabase --version` | 2.116.0 |
| `pnpm db:migrate --help` | Команда доступна; миграция не применялась |
| Мобильный браузер, 390x844 | Успешно на локальном демо; автор, посетитель и покупатель пройдены |

Тесты выполняют SQL/RLS в PGlite, реальные файловые транзакции и серверные обработчики с двумя авторами и двумя покупателями. Проверены закрытый контент и файлы, публикация черновика, сохранение проданного после скрытия/архивации, отдельные права покупок, подписки, возвраты/споры, конкурентные остатки, происхождение Cal-записей, привязка к проверенному email и добровольное подключение Telegram. Внешние запросы в интеграционных тестах подменены фикстурами.

Отдельный HTTP-прогон на свежем локальном демо в режиме разработки прошёл 63 проверки успешных ответов и дополнительные проверки отказов и состояний. Он включает запись, перенос, оплату и отмену встречи, конкуренцию за последний товар, доставку и библиотеку архивного материала. Это не реальные платежи или Cal-бронирования.

Браузерный прогон на локальном демо подтвердил мобильный app-like shell, редактор Page Studio, нижнюю навигацию Page/Clients/Orders/More, панель свойств, добавление всех 25 типов блоков, автосохранение и публикацию. На публичной странице проверены заявка и запись, покупка блока с продолжением после входа, Checkout и библиотека покупателя. Отдельно проверен режим платной страницы: до покупки отдаётся тизер без закрытых блоков, после оплаты страница открывается при повторной загрузке. CRM автора показала созданные обращения и запись. Все внешние операции в этом прогоне оставались локальными демо-данными.

Скрипт HTTP-проверки затем расширен сценарием скрытого купленного материала. Запуск локального production-сервера для этого прогона автоматическая проверка разрешений отклонила: `blocked by policy`, без подробной причины. Обход не выполнялся. Поэтому последний вариант `scripts/smoke-api.mjs` и HTTP-поведение production-сборки ещё не подтверждены полным прогоном. Сценарий скрытого материала отдельно проходит в тестах серверных обработчиков.

## Что остаётся проверить

- Дополнительная визуальная полировка отдельных блоков и полноценная проверка RU/EN на реальных пользовательских сценариях.
- Настоящий Supabase: Auth/SMTP, шаблоны OTP, PostgREST/RLS, Storage и защищённые ссылки. PGlite не заменяет эти проверки. На рабочей машине запуск Docker блокирует отсутствующий WSL.
- Stripe Sandbox/Connect и Cal.com на HTTPS-стенде: аккаунты, ключи, OAuth, вебхуки, оплаты, продления и реальные переносы встреч.
- Inngest, Resend и Telegram: регистрация провайдеров, доставка тестовым получателям, повторы и восстановление после ошибок.
- GitHub Actions: результат отдельного удалённого запуска фиксируется после отправки кода.

Конфигурация: `.env.example`, `supabase/README.md`, `docs/INTEGRATIONS.md`. Демо и Sandbox исключаются из продуктовых метрик; они не подтверждают traction или готовность к реальным платежам.
