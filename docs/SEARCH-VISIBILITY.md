# PAGER: поиск, ответы ИИ и конверсия

Публичная публикация автора теперь отрисовывается в исходном HTML. Бот и посетитель без JavaScript получают одинаковые доступные текст, предложения, вопросы и ответы; клиентский JavaScript добавляет запись, авторизацию и оплату. Закрытый контент подгружается только после серверной проверки покупателя. В HTML, RSC, метаданные и карточки ссылок не передаются черновики и тела платных блоков.

## Что реализовано

- Индивидуальные title, description, canonical, Open Graph и Twitter card; изображение для пересылки ссылки формируется из публичного заголовка и описания. Язык контейнера страницы и метаданных соответствует RU/EN публикации.
- JSON-LD `ProfilePage` / `Person` содержит только видимые сведения из открытого блока профиля. Если такого профиля нет, используется `WebPage`. Фальшивые рейтинги, гарантии результата, статистика подписчиков и неподтверждённые отзывы не добавляются. Социальные ссылки передаются только из доступного блока socials.
- Ответы FAQ присутствуют в HTML внутри стандартных `details` / `summary`, работают без JavaScript и доступны с клавиатуры. Разметка FAQ rich results намеренно не обещается.
- `sitemap.xml` включает опубликованные бесплатные страницы и доступные анонимному посетителю карточки товаров. Canonical карточки не зависит от query-параметра; реальный источник товара проверяется отдельно. Закрытый источник не получает доступ через другой публичный блок.
- `robots.txt` разрешает поисковый обход публичного сайта, включая `OAI-SearchBot`; `GPTBot` для обучения моделей отключён независимо. Кабинеты и API исключены из обхода. Доступ защищает сервер, robots.txt не является механизмом авторизации.
- Демо, localhost, IP-адреса и сайты без корректного HTTPS `PAGER_APP_URL` не индексируются; sitemap в этих режимах пуст. Платные страницы получают noindex, их тело не попадает в структурированные данные. Несуществующий или недоступный товар возвращает 404 анонимному пользователю.
- Основной CTA в начале страницы и закреплённая панель ведут к фактическому публичному блоку записи или форме. Кнопка услуги в каталоге использует только доступный блок записи, явно связанный с этой услугой; без такого блока остаётся ссылка на описание. Каталог сам по себе не является источником записи. Не добавляется обещание фиксированной длительности консультации. Телефон получает крупные кнопки, один столбец сложных блоков, запас под системную панель; на компьютере доступна та же запись без возвращения наверх.
- Просмотры и действия отправляются в собственный endpoint аналитики. Идентификатор посетителя ограничен страницей и браузерной сессией; сырые referrer, User-Agent, поисковые запросы и параметры ссылок не отправляются. Передаются категории источника и устройства, идентификатор события, страницы и выбранного блока. Новая загрузка страницы считается новым просмотром; повторный запуск эффекта React использует тот же идентификатор события. Раскрытие FAQ, галерея и случайный клик по карточке не считаются CTA. Кнопки покупки закрытого блока и всей страницы передают отдельный тип намерения `block_access` / `page_access`; сервер проверяет существование публичного платного предложения, сохраняя контент закрытым. Учитываются Do Not Track и Global Privacy Control. Демо и визиты владельца исключает сервер.

## Редакционные требования к автору

Первый экран должен отвечать: кто вы, кому помогаете, какой результат человек получит, как сделать следующий шаг. Укажите понятную специализацию, реальную локацию или онлайн-формат, стоимость и ограничения услуги, фактический опыт, доступные способы связи. Добавляйте ответы на вопросы о процессе, подготовке, переносе и результате консультации. Короткие прямые ответы, конкретные названия услуг и достоверные подтверждения полезны людям и поисковым системам.

Одна публикация сейчас имеет один язык. `hreflang` не выдумывается: добавить его можно, когда появятся отдельные эквивалентные адреса переводов. Город не превращается автоматически в домашний адрес или LocalBusiness. Видимые данные профиля должны оставаться правдивыми.

## Что нужно проверить на реальном домене

1. Установить `PAGER_DEMO=false` и `PAGER_APP_URL=https://ваш-домен`; завершить настройку реальных Supabase, Stripe и Cal.com. Локальная демонстрация не доказывает работоспособность интеграций.
2. Подтвердить домен в Google Search Console и Bing Webmaster Tools, отправить sitemap, проверить URL Inspection и HTML опубликованной страницы. Проверить, что WAF/CDN разрешает поисковые запросы; при необходимости сверить официальные IP-диапазоны ботов.
3. Проверить JSON-LD в Schema Markup Validator / Rich Results Test, карточки ссылок и фактические страницы на телефоне и компьютере. Измерить LCP, INP и CLS на реальном трафике. Эти полевые показатели нельзя вывести из одного локального теста.
4. Оценивать реальные органические переходы, заявки, подтверждённые записи и оплаченные заказы. Категория `ai` означает распознанный referrer ИИ-сервиса, а не доказанную цитату в ответе; приложения часто не передают referrer. Данные об индексации и показах берутся из поисковых кабинетов, не из локального счётчика кликов.

Индексация, позиция и попадание в ответ ИИ не гарантируются. Для Google AI Overviews / AI Mode применяются обычные требования поиска; отдельный `llms.txt`, специальные ключевые слова или особая schema не обязательны. Поэтому такой файл не добавлен ради видимости выполнения.
