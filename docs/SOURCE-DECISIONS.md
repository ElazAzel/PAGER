# PAGER — карта источников и подключений

Дата решения: 2026-09-03.

Этот документ разделяет материалы, которые помогают разрабатывать PAGER, и
сервисы, которые становятся частью его рабочего runtime. Репозитории навыков,
дизайн-библиотеки и каталог public APIs не должны попадать в bundle приложения
или становиться скрытыми production-зависимостями.

## Что подключаем в runtime

| Сервис | Роль в PAGER | Решение | Когда проверяем |
|---|---|---|---|
| **Supabase** | Postgres, Auth, Storage, RLS | Основная база, авторизация и защищённые файлы. Отдельные Auth/Storage сервисы не добавляем. | После настройки проекта и миграций; затем проверка RLS на двух авторах и двух покупателях. |
| **Stripe Connect + Checkout + Billing** | Подключение аккаунтов авторов, платежи, разовые покупки, подписки, возвраты и споры | Основной платёжный контур. Используем direct charges на аккаунте автора; в пилоте комиссия PAGER равна нулю, комиссии Stripe сохраняются. | Stripe Sandbox с connected account, подпиской, повторным webhook, возвратом и спором. |
| **Cal.com API v2 + embed** | Типы встреч, свободные слоты, бронирование, перенос и отмена | Основной календарь. OAuth — целевой способ, зашифрованный API-ключ — временный fallback до одобрения OAuth-приложения. | После выдачи Cal OAuth и на HTTPS-стенде; отдельно проверить webhook и часовые пояса. |
| **Resend** | Подтверждения, напоминания и служебные письма на русском и английском | Основной email-канал. Тексты хранятся в PAGER; Resend не заменяется случайным email API из каталога. | После верификации домена/отправителя и тестовой доставки. |
| **Inngest** | Надёжная очередь, outbox, повторы и напоминание за 24 часа | Используем для фоновых цепочек записи и уведомлений, а не собственного worker-сервера. | На стабильном HTTPS-стенде с replay/failure-проверками. |
| **Vercel** | HTTPS-деплой и callback/webhook origin | Целевой стенд для проверки внешних провайдеров. | После заполнения секретов и регистрации callback/webhook URL. |
| **Telegram Bot API** | Дополнительная доставка уведомлений автору после явного opt-in | Оставляем опциональным после email. Не импортируем чаты и не управляем членством во внешних сообществах. | После готовности email-контура; только с pairing через бота и проверкой webhook secret. |

В коде адаптеры этих сервисов уже существуют. Это означает готовый локальный
контракт и тестовые заглушки, но не означает, что внешний аккаунт, OAuth,
секреты, домен, webhook или production-база уже подтверждены. Подробная
процедура находится в [INTEGRATIONS.md](./INTEGRATIONS.md).

## Что сознательно не добавляем из public-apis

На MVP не нужен отдельный API для:

- **карты:** блок `map` принимает адрес и ссылку автора; геокодирование добавим
  только при подтверждённой потребности и после отдельного выбора провайдера;
- **авторизации:** Supabase Auth уже покрывает вход покупателя и автора;
- **хранилища:** Supabase Storage уже покрывает защищённые файлы;
- **календаря:** Cal.com является единственным календарным контуром;
- **почты:** Resend является единственным основным каналом уведомлений.

Поэтому сейчас не добавляем Google Calendar, Auth0/Stytch, Dropbox/Google Drive,
SendGrid и случайные geocoding API. Несколько параллельных провайдеров на одном
слое усложнят RLS, webhooks, поддержку и расследование ошибок, не давая пользы
первому пользовательскому сценарию: первая заявка → запись → оплата → повторное
обращение.

## Порядок фактического подключения

1. Настроить отдельный Supabase project для Sandbox и применить миграции/RLS.
2. Создать Stripe platform, подключить тестовый аккаунт автора и зарегистрировать
   signed webhooks.
3. Завершить Cal OAuth registration; до этого использовать защищённый API-key
   fallback на пилотном стенде.
4. Подключить Resend sender/domain и Inngest production endpoint.
5. Провести сквозной сценарий на HTTPS: форма → booking → письмо → Checkout →
   signed webhook → доступ/заказ → reminder.
6. После стабильности email включить Telegram как отдельный opt-in канал.

До прохождения этих шагов PAGER остаётся локальным demo или sandbox. Demo-данные
не считаются живой интеграцией и не попадут в North Star метрики.
